# 工作流程修正

本次修正依據 UI/UX 掃描中的可重現問題。保留使用者指定的互動：代理執行時，輸入下一則文字會讓停止按鈕切換成傳送按鈕。

| 流程 | 修正後行為 |
|---|---|
| 工作階段草稿 | 依工作階段隔離；舊版 crash 草稿只搬遷一次，不在每個空白工作階段重複套用 |
| 非同步送出 | 第一則送達不清除後來輸入的新草稿；失敗後即使已切換畫面，文字與附件仍回復至原草稿 |
| 首次傳送 | 啟動尚在載入模型清單時，傳送路徑等待可用模型；失敗恢復草稿時只合併一次 |
| 編輯排隊訊息 | 使用獨立編輯欄位，儲存或取消皆不覆蓋主輸入框草稿 |
| 立即傳送 | 先預留訊息，收到成功結果後才移除；失敗保留。自動送出會避開預留中的訊息 |
| 重新載入 | 本機佇列持久保存，回復後暫停等待明確操作，避免重複提交可能已送達的訊息 |
| 停止回合 | 保留按鈕切換設計；停止後暫停本機佇列，避免使用者停止後立刻又自動開始下一則 |
| Git 變更辨識 | 以檔案內容指紋偵測等行數替換與縮減修改；同一路徑不重複計數 |
| Git 檢視 | Git 狀態更新時重新讀取選中的 diff；回合變更歸屬綁定工作目錄與工作階段 |
| 排程 | 主資料夾與其他明確授權資料夾的工作階段皆可選取，維持後端授權邊界 |
| 模型選單 | 模型先於預設組合，兩種項目分別計數，省略重複推理程度 |
| 專案入口 | 可選既有專案，另提供新增資料夾，支援方向鍵與 Esc |
| 待辦清單 | 保留手動收合選擇，清單更新不強制展開；展開區限高並可捲動 |
| 摘要 | 將最近助理訊息標為最近回覆，工具次數標為活動紀錄，不冒充任務完成進度 |
| 對話搜尋 | 歷史訊息延後掛載或展開內容後重新套用反白，避免命中內容已可見卻沒有標記 |

回合變更卡片原本的復原會將整個檔案還原至 Git HEAD，包括代理執行前就存在的人工修改。本次移除此不安全入口。檢查器仍保留有明確確認的整檔捨棄操作。尚未提供能保留回合前後人工修改的逐回合快照復原，因此卡片不是可逆的回合 patch，行數是變動檔案目前的 Git 統計。

正常驗證命令以 [validation.md](validation.md) 為準。新增回歸案例涵蓋草稿、佇列保存、傳送預留、排程資料夾、Git 內容辨識及 diff 更新；既有停止按鈕測試繼續保留。
